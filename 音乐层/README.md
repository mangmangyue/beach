## 加一张专辑（不用碰代码）

1. 封面丢进 `音乐层/covers/`，正方形，512×512 左右的 jpg
2. Spotify 里对着专辑「分享 → 复制链接」
3. 在 `albums.js` 里照抄一段贴上去

```js
{
  id: 'modal-soul',
  title: 'Modal Soul',
  artist: 'Nujabes',
  year: 2005,
  cover: 'covers/modal-soul.jpg',
  spotifyAlbum: 'https://open.spotify.com/album/6b08FpNaFFTjc1dJ9DSWfn',  // 整条 url 直接粘
  tracks: [
    { title: 'Feather', duration: '4:31', spotifyTrack: '...' },
  ],
},
```

`spotifyAlbum` / `spotifyTrack` 三种写法都认：裸 id、`spotify:album:xxx`、整条分享链接。

### 不想一条条抄曲目

```bash
python3 音乐层/抓专辑.py "https://open.spotify.com/album/6b08FpNaFFTjc1dJ9DSWfn" --id modal-soul
```

它会把整段数据打印在终端里，复制粘贴进 `albums.js` 就行。
**它不改任何文件**，只打印 —— 粘不粘、粘哪儿，你说了算。

（原理：Spotify 的嵌入页里有一段公开的 JSON，曲目、时长、每首的 track id 都在里面。
不用 API key，因为播放器本来就靠嵌入页。上面那九张就是这么来的。）

也可以**先留空**（`tracks: []`）：唱片架照样收这张碟，
点进去是「整张去 Spotify 听」的页面。

## 关掉窗口之后会怎样（重要）

**关掉窗口不会停音乐。** 唱机是野餐垫上的一个物件 —— 你把唱片放上去，
回沙滩上玩，它还在转。所以「×」只是把窗口**收起来**：DOM 留着，iframe 不重载，歌不断，
场景里的唱片继续转（由 `audio.state.playing` 驱动）。点唱机再打开，还在原来那首。

想停有三个办法：底部那个「停」、场景里调 `audio.pause()`、或者刷新页面。

**一首试听放完会自动接下一首**（底部「连播」可以关掉）。
放到这张碟的最后一首就停，不会绕回第一首 —— 一张唱片放完就是放完了。
窗口收起来的时候也照样接，所以你在沙滩上玩的时候，那张碟会自己放下去。

### 改这块代码之前先读这三条（都是实测踩出来的）

**一 · 换歌必须重建控制器，不能用 `loadUri()`。**
未登录访客的试听，Spotify 只让「刚创建、并且创建时就带着这首 uri」的播放器自动开播。
在已有控制器上 `loadUri()` 换一首，歌会正确装进去（封面歌名都对），
但 `play()` 不生效，停在暂停 —— **第二首之后就再也放不出声**。
重试 `play()`、等 `playback_update`、等 `duration`，全都试过，都不行。
代价是换歌时嵌入框会闪一下重载，比「点了没反应」好太多。

**二 · 「放完了」只能靠「位置追上时长」判断。**
Spotify 不发 ended 事件，**也不会在试听放完之后再发一条「已暂停」**。
30 秒到头它就不吭声了，最后一条 `playback_update` 停在
`position === duration`、`isPaused: false`。等暂停是等不到的。

**三 · 宣告结束之后要挡住后续事件。**
放完之后 Spotify 还会再甩几条「位置=时长、isPaused=false」。
不挡掉的话，刚宣告「停了」又被改回「在放」，**唱片就永远停不下来**。
但要留一个口子：用户自己按 ▶ 重放时位置会退回去，那是真的又开始了。

## 播放器怎么工作的

```
唱片架（封面网格）
   ↓ 点专辑
专辑内页（封面 + 曲目列表）
   ↓ 点某首歌
底部那条 Spotify compact 播放器换成它
```

**底部的「正在放」是常驻的**，不在专辑页里面。
所以从专辑页退回唱片架时 iframe 不会被拆掉，正在听的歌不会断。

### 平台播放器有两条路

| | 用什么 | 拿得到播放状态吗 |
|---|---|---|
| A（默认） | Spotify IFrame API | ✅ 真实的播放/暂停/进度 |
| B（降级） | 朴素 `<iframe>` | ❌ 只知道「装上了这首歌」 |

A 的脚本被拦或 4 秒没到就自动走 B。**两条都不通才画兜底界面**：
封面 + 专辑名 + 曲目列表（每行是外链）+ 一个大的「在 Spotify 中打开」。
**在选第一首歌之前不会创建任何 iframe** —— 不会出现空白的 iframe 框。

### 访客听到什么

未登录 = 30 秒试听，不用注册。已验证：点一首歌就出声，30 秒后 Spotify 自己弹升级卡片。
这不是「只能听 30 秒的播放器」，是**翻唱片架**。

## 给窗口 B（唱机）：你只需要这四行

唱机**不持有任何音频状态**。唱片转不转、唱针落不落，全部由 `audio.state.playing` 驱动。

```js
import { audio } from '../共用/audio.js';
import { openPlayer } from '../音乐层/player.js';

audio.on('change', s => { record.spinning = s.playing; });  // 订阅
onTurntableClick(() => openPlayer());                        // 点唱机 → 弹播放器
```

需要控制播放时用 `audio.play()` / `audio.pause()` / `audio.next()` / `audio.prev()`，
**不要认识 Spotify**。`共用/audio.js` 会转发给当前的音乐后端。

`audio.state` 里有：`trackId / albumId / title / artist / playing / position / duration / ready`。

## 给窗口 A（场景）：环境音的位置已经留好

`共用/audio.js` 的环境层现在是**空的**（阶段 1.9b 才录浪声和黑胶底噪），
但接口已经在了，文件到位之后不用改任何调用方：

```js
audio.defineAmbience('beach', { url: '音效/beach.mp3', gain: 0.6 });
audio.defineSfx('shell', { url: '音效/shell.mp3' });

audio.unlock();          // ENTER 按钮里调，浏览器要求首次交互后才能出声
audio.ambience('beach'); // 循环
audio.sfx('shell');      // 一次性
```

没登记的名字调用是静默 no-op（只在控制台提示一次），**不会报错**。

播放器打开时会自动 `audio.duck(0.25)` 把环境音压低，关闭时 `unduck()` 恢复。

⚠️ `audio.setVolume()` **只管环境层和音效层**。Spotify iframe 的音频不经过我们的
AudioContext，控制不到。所以播放器页脚那个滑块标的是「环境音」而不是「音量」。

## 材质：两套，可以随时换

`ui.setMaterial('glass' | 'bubble')` 改全站默认，
`ui.window({ material: 'bubble' })` 只改一个窗口，
`win.setMaterial(name)` 当场换（验收台顶上那个「玻璃 / 泡泡」就是它）。
**组件代码一行都不用动** —— 差别全在令牌和折射参数上。

| | 玻璃 | 泡泡 |
|---|---|---|
| 感觉 | 有厚度、有重量、边缘硬朗，像一块真镜片压在沙滩上 | 没有重量、随时会破，更接近梦核的「空」 |
| 模糊 | `blur(1.5px)` | `blur(0)` |
| 白色染色 | 5% | 4% |
| 熏色 | 38%（压得实，字站得稳） | 26% |
| 边 | 白色亮边 + 冷暖色散 | 粉—青—金的皂膜虹彩，更宽更软 |
| 内核发光 | 无 | 有（中间一团淡光，顺带托住字） |
| 落影 | 有，压得住 | 几乎没有 —— 影子代表重量，泡泡不该有 |
| 折射 | 窄而狠（band 44 / scale −210） | 宽而软（band 86 / scale −140），色散更重 |

一开始两套差别太小（熏色 38% vs 26%，都带落影），看着像同一个东西。
现在拉开的关键是**熏色差三倍 + 泡泡去掉落影**：
玻璃是「一块压在沙滩上的镜片」，泡泡是「一层膜」，后者应该几乎不存在。

泡泡沿用的是场景里那些许愿泡泡的语言，见 `共用/渲染/28_泡泡形状_圆圈爱心猫狗.png`。

## 调材质时的三条经验（都踩过）

**一 · 「发灰」的来源是白染色，不是不够暗。**
想让面板更透 → 白染色（`--y2k-tint`）降到 3–5%、模糊降到 0–2px。
字读不清了**不要靠加白染色救**，那会让整块面板发乳发灰；
用 `--y2k-plate`（文字垫底）—— 它只垫在有字的那块内容区，封面和空处仍然是透的。

**二 · 折射只有在背后有结构的时候才看得见。**
光秃秃的沙 + 天是一片平滑渐变，弯了也看不出变化。
所以 `场景里试.html` 里特意垫了一块格纹野餐垫 —— 不是装饰，是**判断折射的必要条件**。
真站上去，窗口后面本来就有垫子的格纹、唱机、笔电。

**三 · Spotify 那条播放条的底色改不了，但可以让它不像外来的。**
Spotify 的嵌入播放器没有背景色参数（只有 `theme=0` 这一个开关），
那条的颜色是**它自己从封面取的**——所以 Sons of 1973 是青绿、NewJeans 是蓝。
与其跟它较劲，不如让整块玻璃也染上这张碟的颜色：
`albums.js` 里每张碟都带一个 `accent`（从封面按色相分箱取的主色，
不是平均色——平均色在日落和彩虹封面上会算成一坨泥），
打开专辑时 `win.setAccent()` 把它染到玻璃上。两边同源，那条就成了同一件东西的一部分。
浓度是 `--y2k-album-mix`，不想要就调到 0。

## 材质：liquid glass

参考 `视觉参考/05_交互与UI/` 那两张 iOS 截图。**关键是别做成毛玻璃**，两者完全不同：

| | 毛玻璃（一开始做错的） | liquid glass（现在这版） |
|---|---|---|
| 透明度 | 低，背景糊成一团 | 高，背景看得清是什么 |
| 模糊 | 很重（20px+） | 轻（16px）+ 提饱和 |
| 边缘 | 一条描边 | **一圈会亮的折射边**，是全部的重点 |
| 感觉 | 磨砂塑料片 | 一块有厚度的透明玻璃 |

五件事凑起来才像玻璃：

1. **薄，而且几乎不模糊** —— 这条踩了三次才对。
   **可读性靠「压暗」，不靠「糊」**：模糊 = 磨砂玻璃，看不清背后是什么；
   压暗 = 墨镜片，看得一清二楚只是暗一档。
   一开始 `blur(26px)` + 80% 白 是磨砂；后来 `blur(16px)` + 16% 白 还是磨砂；
   现在 `blur(1.5px)` + 5% 白 + 38% 熏色，才是玻璃。
   背景的「变形」全部交给折射去做，不是交给 blur。
2. **提饱和** —— `saturate(1.95)`，穿过玻璃的颜色更浓，这是「透光」不是「蒙住」
3. **折射边** —— 用 `conic-gradient` 绕一圈，两个对角有亮「热点」。
   用 linear 出来的是均匀描边，像贴纸；conic 才像镜片。所有控件都有这圈边。
4. **熏色** —— 玻璃先垫一层暗的再压白。沙滩下半截是亮的，
   不熏一下浅色的字就没了。真的烟灰玻璃也是这样。
5. **真折射** —— 见下。前四条都做到了还是像塑料片的话，缺的就是这个。

### 真折射（「液态」的那一半）

CSS 的 `backdrop-filter` 只会**模糊**背景，不会**弯折**背景。
但真玻璃有厚度，边缘会把背后的东西掰弯 —— 少了这一下，
再怎么调透明度和亮边，看着都还是一块贴上去的半透明塑料。

做法（业界现在都这么干，参考 [kube.io 那篇](https://kube.io/blog/liquid-glass-css-svg/)
和 [deepika-builds/liquid-glass](https://github.com/deepika-builds/liquid-glass)）：

1. canvas 画一张**位移图**：R 通道存 X 位移、G 通道存 Y 位移，128 = 不动。
   中间一大片全是 128（内部不变形），只有贴着圆角的一条带子里有值 —— 那是玻璃的厚边。
2. SVG 里 `<feImage>` 读这张图，`<feDisplacementMap>` 拿它去推背景像素。
3. 推三遍，scale 差一点点，分别只留 R / G / B，再 `feBlend mode="screen"` 混回去
   —— 边缘就有了色散，跟真镜头一样。
4. `backdrop-filter: url(#滤镜) blur() saturate()`

实现在 `共用/ui.js` 第 2 节（`refract()`），窗口自动接上。
想给别的元素用：`ui.refract(el, { radius, band, scale, chroma })`。

**两个非踩不可的坑**（都在代码注释里也写了）：

- filter 上必须写 `color-interpolation-filters="sRGB"`。不写的话 SVG 默认走 linearRGB，
  会把「128 = 不动」这个中性灰算歪，**整块面板都跟着漂**。
- **只有 Chromium 支持把 SVG 滤镜用作 `backdrop-filter`。**
  Safari 和 Firefox 做不出来，`ui.canRefract` 会是 false，自动退回纯 CSS 的玻璃
  —— 还是好看的，只是边缘不弯。

**性能**：位移图是同步画的，一开始放在开窗那一帧里，把窗口卡了 104ms。
现在两处改动之后是 14ms：内层循环不再每像素分配临时对象（十万个对象就是那 100ms 的来源），
第一张图推到下一个宏任务算，开场动画正好盖住那一拍。
尺寸不变就不重画（`ResizeObserver` + 尺寸签名）。

**只给窗口用**。里面的按钮和卡片背后是平的玻璃，弯了也看不出来，纯浪费。

### 还有两处「灵动」

- **高光跟着指针走**：`pointermove` 只写 `--y2k-mx / --y2k-my` 两个数，画的事全在 CSS。
  两层（一小团亮芯 + 一大片晕开的光）叠起来才像光在湿面上滑，一层就是个手电筒光斑。
  用 `@property` 把这两个属性声明成百分比，浏览器才肯补间 —— 那点「粘」就是这么来的。
- **开窗带一点回弹**：`--y2k-ease-liquid`，稍微涨过头再落定，像一滴液体落下去。

想调，只改 `ui.css` 第 1 节这几个令牌，组件规则一行都不用动：

| 令牌 | 管什么 |
|---|---|
| `--y2k-shade` | 熏得多暗（字读不清就加大） |
| `--y2k-tint` | 玻璃多白（越大越不透明） |
| `--y2k-blur` | 模糊多少（**别往上加**，一加就变回毛玻璃） |
| `--y2k-core` | 内核发光（只有泡泡非透明） |
| `--y2k-plate` | **文字垫底**。想更透但字要读得清，动这个，别去加白染色 |
| `--y2k-album-mix` | 跟当前唱片染色的浓度 |
| `--y2k-spec-a` `--y2k-spec-r` | 指针光斑的浓度和半径。**要克制** —— 一开始 22%/280px，压在曲目列表上像块跟着鼠标跑的油渍，现在 10%/150px |
| `--y2k-rim-*` | 折射边的亮度和色散 |

真折射的参数不在 CSS 里，在 `ui.js` 里 `createWindow` 调 `refract()` 那一行：
`band`（厚边多宽）、`scale`（掰多狠，负数=凸透镜）、`chroma`（色散多少）。

因为玻璃很薄、背后是暗沙滩，**文字是浅色的**（两张参考图都是浅字）。
想换回「浅底深字」，改 `--y2k-ink` 那几个 + `--y2k-shade` 即可。

不支持 `backdrop-filter` 的浏览器会自动退回一块不透明的暗板 —— 不好看，但读得清。

## 给以后的弹窗：ui 怎么用

```js
import { ui, h } from '../共用/ui.js';   // 会自动注入 ui.css，不用再写 <link>

const win = ui.window({ title: 'WISH', sub: '许愿', width: '480px', height: '460px' });
win.setView(ui.scroll(ui.section(
  ui.legend('放一个愿望进海里'),
  ui.field({ label: '写点什么', textarea: true, placeholder: '……' }),
)));
win.setFooter(ui.spacer(), ui.btn({ label: '放进海里', variant: 'primary' }));
```

`ui.window` 自带：拖动、Esc 关闭、点遮罩关闭、焦点关在窗口里、开合动效、关闭后焦点还原。
多层导航的窗口（像播放器）传 `fixedHeight: true`，换内容时窗口才不会一跳一跳。

组件清单和活的示例看 `UI组件预览.html`。想换皮改 `ui.css` 顶上的**设计令牌**，
不要去改组件规则。
